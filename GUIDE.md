# VN Studio — документация и гайд

> Конструктор и плеер визуальных новелл с ИИ-нарратором. Версия 0.9.0.
> Внутреннее имя пакета — `novel-forge`, бренд в интерфейсе — **VN Studio**.

Это полное руководство: от «что это и как запустить» до тонкой настройки ИИ,
оформления и устройства данных. Документ разбит на две части — **гайд для
пользователя** и **справочник для разработчика**.

---

## 1. Что это такое

VN Studio — это **клиентское веб-приложение** (одна страница, без бэкенда), в котором
можно:

- **собрать** визуальную новеллу в духе «Клуба Романтики»: лор, персонажи, спрайты по
  эмоциям, статы, музыка, фоны, CG;
- **играть** в неё, где сам сюжет в реальном времени пишет большая языковая модель
  (LLM) по вашему API-ключу, а движок превращает её структурированный ответ в сцену:
  фон, спрайт с нужной эмоцией, реплика с тайпрайтером, выборы, изменения статов.

**Аналогия:** SillyTavern (ядро LLM) + Ren'Py (презентация) + конструктор без кода.

Три принципа, на которых всё держится:

1. **Всё локально.** Проекты, ассеты и сейвы хранятся на вашем устройстве. Никакого
   сервера с вашими данными нет.
2. **Свой ключ (BYO API key).** Ключи лежат только в `localStorage` вашего браузера и
   уходят напрямую выбранному провайдеру. В файлы проекта/экспорта они **не пишутся**.
3. **ИИ не видит ваши файлы** — только «манифест»: список id ассетов с именами и
   тегами. Если модель выдумает несуществующий id/эмоцию/настроение — игра не падает,
   срабатывает fallback (например, эмоция → `neutral`).

## 2. Быстрый старт

Нужен установленный **Node.js 18+**.

### Вариант A. Режим разработчика (проще всего попробовать)

```bash
npm install
npm run dev        # откроется http://localhost:5173
```

Прочие скрипты:

```bash
npm run build      # продакшн-сборка в dist/
npm run preview    # предпросмотр собранного
npm run lint       # проверка типов (tsc --noEmit)
```

### Вариант B. Лаунчер — как отдельное приложение (рекомендуется для игры)

```bash
bash launcher/start-omaya.sh
```

Скрипт сам: при необходимости обновит код (`git pull`), поставит зависимости, соберёт
приложение, поднимет локальный сервер на `http://localhost:5173/` и откроет его.
Работает в **Termux (Android)**, **Linux** и **macOS**.

Что даёт лаунчер по сравнению с `npm run dev`:

- **Встроенный прокси `/__proxy`** — запросы к ИИ идут через локальный сервер
  (server-side, как в SillyTavern), поэтому **нет проблем с CORS**: работают любые
  провайдеры (DeepSeek, нативный Gemini и т.д.), а не только те, кто отдаёт CORS-заголовки.
- **Файловое хранилище на диске** (`vn-data/`) — данные лежат реальными файлами и
  **переживают очистку данных браузера** (см. §17).
- **Установка как PWA** — ярлык на рабочем столе / домашнем экране и окно без адресной
  строки. Подробности — в `launcher/README.md`.

> ⚠️ **Не меняйте порт 5173, если уже играли.** IndexedDB привязана к origin вместе с
> портом: смена порта покажет «пустую» библиотеку (данные целы, но под другим адресом).

## 2.1 Два режима — развилка на входе

При первом запуске приложение спрашивает, с чем работаем:

| | 🎭 Визуальная новелла | 💬 Классический РП |
|---|---|---|
| Экран | сцена со спрайтами и фонами | лента переписки |
| Ответ модели | структурированный JSON: биты, эмоции, музыка, выборы | обычная проза, стримингом |
| Ход игрока | кнопка выбора или свой текст | только свой текст |
| Ассеты | нужны: фоны и спрайты | не нужны, только аватарки |
| Расширения | телефон, инвентарь, деньги, CG-студия | — |

Это **не настройка по вкусу, а два разных приложения на одном движке**: у режимов
раздельные библиотеки проектов, свои конструкторы и свои пресеты промпта. Выбор
запоминается; сменить его можно значком слева в верхней панели — он же показывает,
в каком режиме вы сейчас.

**Проект принадлежит одному режиму.** Чтобы вести тот же сеттинг в другом, есть
кнопка **«Адаптировать»** на карточке проекта: она делает КОПИЮ в другом режиме —
лор, лорбук, персонажи и статы переезжают, спрайты/фоны/музыка в текстовый режим не
едут (им там негде показаться). Оригинал не трогается, прогресс не копируется:
история новеллы состоит из JSON-ходов и в ленте переписки читалась бы как мусор.

Общего у режимов — движок: память со свёрткой, Game Master, лорбук, макросы,
подключение к ИИ, правила-регэкспы, сейвы и чекпоинты работают одинаково.

## 3. Базовые понятия

| Термин | Что это |
|---|---|
| **Проект** | Одна новелла целиком: лор, персонажи, статы, ассеты, конфиг ИИ, тема оформления. |
| **Режим повествования** | `Визуальная новелла` (спрайты, сцены, выборы) или `Классический РП` (только текст, игрок пишет сам). Задаётся в настройках проекта, см. §8.1. |
| **Ассет** | Файл: фон, спрайт, CG, музыка, SFX, иконка. У ассета есть имя и теги. |
| **Эмоция** | Закрытый словарь из **11** значений (см. §21). Спрайты привязываются к эмоциям. |
| **Наряд (outfit)** | Открытый пер-персонажный тег костюма (например, `school`, `armor`). Независим от эмоций. |
| **Стат** | Числовой параметр (отношения, кредиты, здоровье…) с границами, иконкой, описанием для ИИ. |
| **Роль персонажа** | protagonist / love_interest / important_character / npc. Влияет на отрисовку и промпт. |
| **Аудио-настроение** | Закрытый словарь из **8** базовых настроений музыки (+ ваши кастомные). ИИ выбирает настроение, движок — трек. |
| **Память** | Сжатие истории: живое саммари + меморибук фактов + опциональная векторизация. |
| **Game Master (GM)** | Динамическое состояние мира: календарь, локации, досье персонажей, отношения, события, повестка. |

## 4. Верхняя панель (иконки)

Единая неоново-стеклянная панель наверху. Слева — логотип **VN Studio**. Справа — ряд
иконок-кнопок (у каждой всплывающая подсказка на выбранном языке интерфейса):

- 📦 **Пресет промпта** — слои системного промпта, язык нарратива, стиль, jailbreak (§8).
- 🔌 **Подключение к ИИ** — провайдер, адрес, ключ, модель, тест соединения (§7).
- 🎛 **Game Master** — *только в плеере* — мир/календарь/досье/память (§9).
- ▦ **Расширения** — *только в плеере* — доп. инструменты и импорт.
- 📄 **Логи** — события и ошибки (со счётчиком ошибок-бейджем).
- 🌐 **Язык интерфейса** — переключатель RU/EN.

> В плеере порядок иконок особый: язык — первым, а игровое **бургер-меню ☰** — самым
> последним справа (это меню самой игры, см. §10).

## 5. Библиотека

Стартовый экран. Здесь:

- **Новый проект** — создаёт пустую новеллу.
- Карточка каждого проекта: обложка, название, кнопки **▶ Играть** и **✎ Редактировать**.
- **Копировать проект** — делает независимый дубль (новые id, скопированные ассеты и
  тема оформления). Удобно, чтобы ветвить контент, не ломая оригинал.
- **Экспорт/Импорт** — проект целиком в один `.zip` (см. §16).

## 6. Конструктор

Открывается по **✎ Редактировать**. Вкладки:

1. **Настройки** — название, обложка, возрастной рейтинг (SFW / Mature). *Тон и жанр
   здесь не задаются* — они живут в пресете промпта (§8).
2. **Лор** — описание мира, арка сюжета, стартовая сцена, правила повествования.
3. **Персонажи** — анкеты + роли (протагонист ♦ / любовный интерес ♥ / важный ★ / NPC) +
   **SpriteBinder**: сетка из 11 слотов эмоций. Обязателен `neutral`. Загрузка спрайтов:
   - по одному в слот;
   - **zip-пачкой** по неймингу `имя_эмоция.png` (например `ares_joy.png`) — распознанные
     раскладываются по слотам, нераспознанные складываются в отдельный блок с
     перетаскиванием в нужный слот;
   - **наряды**: у персонажа можно завести доп. костюмы (открытые теги) со своим набором
     спрайтов по эмоциям.
4. **Статы** — имя, мин/макс/старт, видимость в HUD, иконка, описание для ИИ (когда
   стат должен меняться). Стат можно **привязать к персонажу** — тогда он трактуется как
   параметр отношений с ним (несколько статов можно привязать к одному персонажу).
5. **Ассеты** — мультизагрузка фонов/спрайтов/музыки/CG/SFX/иконок, автотеги, чипы-теги.
   Для музыки — выбор **аудио-настроения** (можно несколько треков на одно настроение).
6. **Лорбук** — записи со словами-триггерами (как в SillyTavern): встречается ключ в
   истории — запись подмешивается в контекст. Есть тест-поле для проверки срабатывания.

Наверху конструктора **валидатор** подсвечивает проблемы (нет стартовой сцены, у
персонажа нет `neutral`-спрайта и т.п.).

## 7. Подключение к ИИ (🔌)

- **Провайдер:** OpenAI-совместимый или Anthropic.
- **Base URL** и **модель** (можно подтянуть список моделей запросом `/models`).
- **API-ключ** — хранится только в `localStorage`.
- **Тест соединения** — быстрая проверка, что ключ/адрес рабочие.
- Подключение **глобальное** (одно на все проекты), но у отдельных подсистем — саммарайзер,
  векторизация, кастомный селектор ассетов — можно задать своё отдельное подключение.

> При игре через лаунчер запросы идут через `/__proxy` (без CORS). При `npm run dev`
> провайдер должен сам отдавать CORS-заголовки, иначе используйте лаунчер.

## 8. Пресет промпта (📦)

Системный промпт собран **слоями** (архитектура в духе SillyTavern):

1. **Ядро** — вшитый, неизменяемый JSON-контракт: формат ответа, правила ролей и
   отрисовки, закрытые словари эмоций/настроений, политика fallback. Показывается только
   для чтения.
2. **Стиль/тон** — стиль-пресет («в духе Клуба Романтики», «тёмный», «комедийный»,
   «классическая новелла») или свой `customStyle`, плюс **язык нарратива** (RU/EN —
   независим от языка интерфейса!).
3. **Jailbreak** — включается тумблером, свой текст (для mature-контента).
4. **Prefill** — затравка ответа ассистента (для Anthropic — реальный префилл, для
   openai-совместимых — хвостовое assistant-сообщение).

Пресет **глобальный и полностью редактируемый** (как в Таверне): тумблеры блоков,
температура, бюджет контекста, продвинутые блоки на заданной «глубине», токен-счётчик.
Есть импорт/экспорт пресета. Дефолтный пресет усилен правилом «раскрывать характер через
действия И прямую речь» — ирония/резкость персонажа слышны в его репликах.

Пресетов **два — по одному на режим повествования** (переключатель вверху панели):
у новеллы и у текстового РП разные наборы блоков, потому что половина блоков одного
режима другому только мешает. Какой из них применится, решает настройка проекта.

**Метод обработки промпта** (там же, отдельной карточкой) — как собранный запрос
приводится к форме, которую принимает конкретный шлюз. Семантика скопирована с
SillyTavern намеренно, это вопрос совместимости, а не вкуса:

| Метод | Что делает | Когда нужен |
|---|---|---|
| Без обработки | Шлёт как собрано | Шлюз всё принимает |
| Склейка ролей | Соседние сообщения одной роли — в одно | По умолчанию; подходит почти всем |
| Полустрогая | + системные сообщения внутри диалога становятся `user` | Шлюз ругается на system в середине |
| Строгая | + заглушка `user` сразу после системной части | Claude и Gemini напрямую |
| Одним сообщением | Весь запрос — одно `user`-сообщение, реплики подписаны именами | Ручки, принимающие ровно одно сообщение |

**Правила-регэкспы** — то, что в Таверне живёт отдельным расширением, здесь стоит в
ядре. Каждое правило — одна замена: что найти (регулярное выражение), чем заменить,
к чьему тексту применить (ответ ИИ / ход игрока / оба) и **где**: `На экране`
(в истории и в контексте останется исходный текст), `В запросе` (модель увидит
изменённый, вы — исходный) или `Везде`. В замене работают `$1`…`$9` и `{{match}}`.
Порядок в списке — порядок применения; рядом с каждым правилом живая проба на
тексте, так что довести его до ума можно не открывая игру. Есть готовые заготовки:
убрать «Имя:» перед репликой, спрятать `(OOC: …)`, кавычки-лапки в ёлочки.

**Макросы** — справка прямо в панели пресета. Имена совпадают с Таверной там, где
совпадает смысл: `{{user}}`, `{{char}}`, `{{persona}}`, `{{description}}`,
`{{personality}}`, `{{scenario}}`, `{{random:а,б,в}}`, `{{roll:d20}}`. Сверх этого —
свои: `{{stat:Имя}}`, `{{scene}}`, `{{turn}}`, `{{location}}`, `{{lastMessage}}`.
Осознанное отличие: `{{time}}` и `{{date}}` — это **внутриигровые** часы, а не время на
устройстве (оно доступно как `{{realtime}}` / `{{realdate}}`). Свои макросы проекта
задаются в настройках проекта и раскрываются везде, где работают встроенные.

## 8.1 Режим классического РП

Тот же движок — другой способ вести историю. Как выбирается и как переносится
сеттинг между режимами — см. §2.1.

Что общее: движок памяти со свёрткой, Game Master, лорбук, заметки автора, сейвы и
чекпоинты, подключение к ИИ, слэш-команды. Проект остаётся проектом — с несколькими
персонажами и оформленным миром, а не одной карточкой.

**Конструктор в этом режиме короче:** вкладки «Ассеты» нет вовсе, у персонажа нет
спрайтов и нарядов (только аватарка), в настройках нет денег — остаётся стартовая
дата, с которой пойдут внутриигровые часы.

Что отличается:

| | Визуальная новелла | Классический РП |
|---|---|---|
| Формат ответа | один JSON-объект по схеме (биты, эмоции, музыка, выборы) | обычная проза |
| Экран | сцена со спрайтами и фонами, реплики по клику | лента переписки |
| Ход игрока | кнопка выбора или свой текст | только свой текст |
| Выборы | каждый ход | нет вовсе |
| Спрайты, фоны, музыка, телефон, CG | есть | нет |
| Состояние мира | внутри JSON-ответа | служебный блок `<state>` в конце ответа + инфобокс под ним |
| Показ ответа | целиком, затем биты по клику | стриминг по мере генерации |
| Переделать ответ | перегенерация заменяет | свайпы: варианты копятся, между ними стрелки |

**Не писать за игрока.** Главное правило режима держится тремя независимыми способами
сразу, потому что одним промптом оно не держится: блок «🚫 Не писать за игрока» в начале
запроса, короткое напоминание в самом конце (после всей истории) и техническая страховка
— стоп-строка провайдеру плюс срез хвоста ответа, если модель всё-таки начала говорить
за героя. Страховку можно выключить галочкой в панели пресета.

**Служебная сводка состояния.** Модель дописывает в конец ответа блок `<state>…</state>`
с часами, досье и событиями — движок его вырезает из показа и мержит в Game Master.
Благодаря этому память, досье персонажей и внутриигровое время работают в текстовом
режиме так же, как в новелле. Блок можно выключить: история продолжит идти, но Game
Master перестанет обновляться сам.

**Лента переписки.** Показывает ровно то, что уходит в контекст — `state.history`, без
второго хранилища. Любое сообщение можно отредактировать (правится сырой текст, тот
самый, что видит модель) или удалить; последний ответ — перегенерировать. Свёрнутые в
память ходы из ленты исчезают: они уже в журнале эпизодов (Game Master → Память).

**Стриминг.** Ответ печатается по мере генерации. Служебные потроха при этом не
мелькают ни секунды: пока идёт `<thinking>`, на экране пусто, а всё от начала
`<state>` и до конца отрезается прямо в потоке. Если шлюз не умеет потоковую
выдачу — движок молча переспрашивает обычным запросом, и ход не теряется. Через
лаунчер поток тоже работает: локальный прокси пропускает `text/event-stream` как
есть, не буферизуя.

**Свайпы.** Стрелки `‹ 1/3 ›` у последнего ответа. Правая стрелка на последнем
варианте генерирует новый, не выбрасывая прошлые; левая возвращает к предыдущему.
Возврат — не просто подмена текста: у каждого варианта своя сводка `<state>`, и
состояние мира пересобирается из неё, поэтому часы и досье соответствуют тому
варианту, который сейчас на экране. Единственное исключение — если вкладку
перезагружали: снимка состояния до хода уже нет, тогда меняется только текст, и
движок честно пишет об этом в лог.

**Инфобокс состояния** (в духе Horae) — компактная плашка под каждым ответом: где
мы, сколько времени, кто в сцене, чем занят, что о ком известно, что произошло.
Свёрнута до строки чипов, разворачивается по клику. Рисуется НЕ регэкспом по
тексту, а по разобранному блоку `<state>` — тем же данным, что кормят Game Master,
поэтому не ломается от вольностей в форматировании. Выключается в панели пресета.

**Аватарки.** У персонажа — в конструкторе, кружком слева от имени (спрайт
подставляется, пока своей нет). У героя — кликом по своей аватарке прямо в ленте;
она принадлежит **прохождению**, а не проекту, потому что одну историю можно вести
разными персонажами. Нет ни той, ни другой — буква имени на цветном кружке, цвет
считается от имени, так что человек всегда одного цвета. У ответа модели лицо не
одно: показывается стопка тех, кого модель назвала в сводке этого хода.

**Размер ответа** — пресеты от «Короткого» (120–300 слов) до «Полотна» (1600–3000)
в панели пресета, плюс ползунки для своих значений. Потолок ответа движок считает
от верхней границы, так что «Полотно» не обрежется на середине.

---

## 8.2 Ассистент-соавтор (вкладка 🤝 в конструкторе)

Чат, который видит проект целиком и умеет его править. Есть в обоих режимах.

**Что он видит:** описание мира, арку, стартовую сцену, правила повествования, все
карточки персонажей, заголовки и ключи лорбука, статы. Содержимое записей лорбука —
только по запросу: иначе каждый вопрос стоил бы как целый ход игры.

**Что он может изменить:** завести и править персонажей, добавлять и править записи
лорбука, заменять описание мира / арку / стартовую сцену / правила, заводить статы.
Ассеты, спрайты и настройки подключения — не трогает.

**Как это безопасно.** Правки идут не свободным текстом, а явными операциями, и у
каждой три свойства: она названа человеческой строкой («Создан персонаж «Мира»»),
показана списком под ответом и **отменяется одной кнопкой**. Откат хранится вместе с
сообщением, поэтому переживает перезагрузку вкладки. Нет блока правок в ответе —
ничего не изменилось; это нормальный и частый случай, на вопрос отвечают текстом.

**Личность** настраивается своим текстом и общая для всех проектов — это ваш
помощник, а не свойство сеттинга. Пусто — работает дефолтная: спокойный редактор без
воды. Правила о том, КАК он правит проект, добавляются поверх и не отключаются.

Быстрые кнопки под полем ввода: придумать персонажа, дожать карточку, предложить
записи лорбука, разобрать описание мира, предложить стартовую сцену.

## 9. Game Master (🎛, только в плеере)

Динамическое состояние мира, которое ИИ обновляет каждый ход (подход в духе Horae):

- **Календарь** — год/месяц/день/время + локация. Месяцы настраиваются. Дату/локацию
  можно показывать в игре плашкой HUD (§10).
- **Досье персонажей** и **связи-отношения** между ними.
- **События** — ведутся как меморибук.
- **Повестка (agenda)** — задачи/планы.
- **Память** — сжатие истории: живое саммари обновляется по счётчику сообщений;
  меморибук фактов; опциональная **векторизация** (эмбеддинги MiniLM в веб-воркере) для
  подтягивания релевантных кусков.

Всё это можно править прямо в игре, есть «волшебная палочка» автозаполнения.

## 10. Плеер — как играть

Запуск: **▶ Играть**. Сначала — **экран запуска**: Продолжить / Загрузить сейв / Новая
история (новая история спросит — стереть прогресс или начать параллельное прохождение).

Экран игры (неоново-стеклянный дизайн):

- **HUD сверху слева** — стеклянная плашка календаря/локации (если включена в GM) и ряд
  компактных пилюль статов (иконка + значение, с анимацией «+2» при изменении).
- **Спрайт говорящего** — один активный персонаж, кроссфейд между эмоциями (не мигает).
- **Реплика** — тег имени говорящего + пузырь с тайпрайтером. Клик — доиграть тайпрайтер
  или перейти дальше. Мысли/нарратив — своим стилем.
- **Нижняя панель ввода** — поле «ваши слова или действие героя», кнопки команд и
  отправки. Свой ввод = дословная реплика/действие героя.

### Слэш-команды (в поле ввода)

| Команда | Действие |
|---|---|
| `/bg <теги>` | Сменить фон (ищет по тегам/имени; не нашёл — просит ИИ) |
| `/ooc <текст>` | Ремарка вне сюжета (out-of-character) |
| `/regen` | Перегенерировать последний ход |
| `/mute` | Выключить/включить звук |
| `/help` | Подсказка по командам |

### Игровое бургер-меню ☰ (справа вверху)

История · Сейвы/чекпоинты · Микшер звука · **🎨 Оформление** (§12) · Генерация ассетов ·
Правка в игре · Перегенерация.

### Выборы

Иногда ИИ предлагает варианты выбора (кнопки). Вариант может быть **платным** — стоить
очков стата; если не хватает — он заблокирован. Свободный ввод в консоли доступен всегда.

## 11. Прохождения и чекпоинты (ветки)

- **Автосейв** ведёт «курсор» текущего прохождения — он переживает перезагрузку.
- **Ручные чекпоинты** — именованные точки, от которых можно **ветвиться**: создать,
  переименовать, удалить, перейти в другое прохождение, увидеть точку разветвления.
- Реестр прохождений не хранится отдельно — он **выводится из метаданных сейвов**
  (`playthroughId`, `kind`, `checkpointId`…), поэтому устойчив к очистке браузера.

---

## 12. Мастерская оформления (🎨) — пер-проектные темы

Открывается из бургер-меню плеера. Настраивает вид **только экрана игры** (не конструктора
и не библиотеки). Тема **пер-проектная** — хранится в самом проекте и едет с ним при
копировании/экспорте/шаринге; у каждой игры своя.

Что настраивается:

- **Акцентный цвет** — пресеты + пипетка + hex. Красит тег имени, кнопку отправки,
  подсветку выборов, рамку фокуса, спиннер.
- **Пузырь реплики** — цвет (пресеты/пипетка/hex) и **прозрачность** (ползунок). Влияет
  на пузырь реплики и кнопки выбора.
- **Шрифт** — быстрые пресеты Google Fonts (Lora, Roboto Slab, Merriweather, Comfortaa,
  PT Serif) **или** вручную: имя семейства + ссылка на таблицу стилей (`@import`/`link`).
- **Размер текста** — ползунок 80–160%, масштабирует текст реплик и выборов.

Есть **живой предпросмотр** и кнопка **Сбросить**. Настройки сохраняются вместе с проектом.

## 13. Мгновенная отмена и перегенерация

- Генерацию хода можно **отменить** — интерфейс мгновенно откатывается к предыдущему виду,
  запрос прерывается (AbortController), ввод не теряется.
- **Перегенерация** заменяет последний ход новым. Новый запрос корректно вытесняет
  предыдущий «в полёте».

---

## 14. Генерация изображений и правка прямо в игре

- **Генерация ассетов** (в игре) — «Создать фон/CG»: ИИ по контексту сцены собирает
  короткий промпт для картинки, изображение генерится image-провайдером
  (OpenAI-совместимый `/images/generations`, ключ отдельный) и кладётся в проект с
  тегами — модель сможет переиспользовать его в следующих сценах.
- **Правка в игре** — мини-формы добавить/поправить персонажа, фон, стат прямо во время
  игры; изменения сразу попадают в манифест и сохраняются.

---

## 15. Роли ИИ: Нарратор и Селектор ассетов

Работу можно разделить на две «головы»:

- **Нарратор** — пишет сюжет и по умолчанию сам выбирает спрайты/эмоции/наряды.
- **Селектор ассетов** — отдельно уточняет выбор ассетов. Источник настраивается:
  - `main` — оставить выбор Нарратора (по умолчанию, самый качественный);
  - `custom` — отдельный LLM-вызов на классификацию (можно своё подключение);
  - `local` — локальные эмбеддинги (MiniLM) без сети (работает грубее).

Любой результат ре-валидируется по закрытым спискам; ошибка селектора молча оставляет
выбор Нарратора.

## 16. Импорт, экспорт, копирование, шаринг

- **Экспорт/импорт проекта** — один `.zip` со всем (лор, персонажи, статы, ассеты,
  конфиг, тема). Ключи API в архив **не попадают**.
- **Копирование проекта** — независимый дубль внутри библиотеки.
- **Шаринг** — превью-карточка проекта с дисклеймером.
- **Импорт карточек** — поддерживаются карточки персонажей и лорбуки из SillyTavern /
  Janitor.

## 17. Где лежат данные

Два уровня хранения (при игре через лаунчер):

1. **Диск — источник истины.** Локальный сервер пишет реальные файлы в `vn-data/`:

```
vn-data/
  <project_id>/
    project.json                                   — метаданные, лор, статы, конфиг, тема, мета ассетов
    characters/<имя>/expressions/<эмоция>.<ext>    — спрайты дефолтного наряда
    characters/<имя>/outfits/<наряд>/<эмоция>.<ext> — спрайты доп. нарядов
    backgrounds|music|cg|sfx|icons/ ...            — ассеты реальными файлами
    saves/<slot>.jsonl                             — сейвы построчно (JSONL: meta + state + история)
```

Путь настраивается: `DATA_ROOT=/путь bash launcher/start-omaya.sh`.

2. **IndexedDB (`novel-forge`) — быстрый кэш** поверх диска. При первом запуске новой
   версии проекты из IndexedDB один раз мигрируют на диск, дальше `syncStorage()` сверяет
   их при старте.

**Итог:** очистка данных сайта в браузере **не уносит прогресс** — файлы лежат на диске
вне браузерного хранилища. При игре только через `npm run dev` (без лаунчера) данные
живут лишь в IndexedDB — делайте бэкап экспортом.

## 18. Приватность и ключи

- API-ключи хранятся **только** в `localStorage` этого устройства.
- В `project.json`, экспортные `.zip` и файлы данных ключи **не записываются**.
- Через лаунчер ключ уходит не дальше вашего же локального прокси (`127.0.0.1`) → провайдеру.

## 19. Устранение неполадок (FAQ)

- **Приложение долго не появляется.** Заставка загрузки показывает, на каком шаге оно
  стоит: `загрузка кода` — качается сам бандл, `хранилище проектов` — синхронизация с
  папкой `vn-data/` (может быть долгой при большом числе проектов), `интерфейс` — первый
  рендер. Если счётчик замер на одном шаге дольше минуты, ошибка будет в консоли браузера.
- **Библиотека пустая после обновления/смены адреса.** Проверьте порт — должен быть тот
  же (5173). Данные привязаны к origin+порту.
- **«Failed to fetch» / CORS при запросе к ИИ.** Играйте через лаунчер (прокси без CORS)
  или выберите провайдера с CORS-заголовками.
- **Персонаж не показывается спрайтом.** Нет подходящего спрайта — сработал fallback до
  `neutral`, а если и его нет — рендерится только имя+текст. Загрузите хотя бы `neutral`.
- **Эмоция «не та».** Если у персонажа нет спрайта под эмоцию, показывается ближайший
  по fallback-цепочке. Проверьте, что нужные эмоции загружены; либо переключите Селектор
  ассетов на `main` (🎛 → вкладка селектора).
- **Спрайты «дёргаются» при частой смене эмоций.** Это исправлено кроссфейдом; если
  видите резкость — убедитесь, что стоит свежая сборка (лаунчер пересобирает сам).
- **Нет места на диске сессии/сборки.** Удалите `dist/` и кэши, пересоберите.
- **Пропал звук.** Проверьте микшер (бургер → Микшер) и `/mute`.

## 20. Горячее — коротко

- Свой текст в консоли = дословное действие/реплика героя.

- Клик по реплике — доиграть тайпрайтер / дальше.

- Экспорт `.zip` — ручной бэкап, всегда актуален.

## 24. Ключевые инварианты

- **JSON-контракт ИИ↔движок нерушим:** галлюцинация id/эмоции/настроения **никогда не
  крашит** игру (repair/fallback в `responseParser`).
- **Единая точка миграции** данных — `normalizeProject()` в `factory.ts`. Любая старая/
  импортированная/частичная форма проекта приводится к актуальной модели там.
- **Ключи API** — только в `localStorage`, никогда в данных/экспортах.
- **Тема оформления** — пер-проектная (`project.playerTheme`), применяется CSS-переменными
  на корне плеера (`--pl-accent*`, `--pl-bubble-bg`, `--pl-font-scale`), не затрагивая
  конструктор/библиотеку.
- **Порт 5173** фиксирован (origin IndexedDB).

## 25. Локальный сервер лаунчера (`launcher/serve.mjs`)

Zero-dependency Node-сервер:

- раздаёт `dist/`;
- `/__proxy` — форвардит запрос к провайдеру по заголовку `x-target-url` (server-side,
  без CORS);
- `/__data/*` — файловое API для чтения/записи `vn-data/` (источник истины).

Запуск: `bash launcher/start-omaya.sh` (переменные `PORT`, `HOST`, `DATA_ROOT`,
`NO_PULL`). Установка как PWA — `launcher/README.md`.
