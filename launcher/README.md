# Novel Forge — установка как отдельного приложения (лаунчер)

Novel Forge — это **PWA** (Progressive Web App). После установки у него появляется
**ярлык на рабочем столе / домашнем экране**, и он открывается **в отдельном окне
без адресной строки и вкладок браузера** — как обычное приложение (аналог того, как
это сделано в SillyTavern).

Данные (проекты, ассеты, сейвы) хранятся локально в браузере/движке приложения.
API-ключи — только в этом устройстве.

---

## Android (Termux) — как в Таверне

1. Установите зависимости и запустите лаунчер:
   ```bash
   cd VN-OmayaEngine
   ./launcher/start-omaya.sh
   ```
   Скрипт соберёт приложение, поднимет локальный сервер `http://localhost:5173`
   и откроет его в браузере (Chrome).

2. В Chrome нажмите меню **⋮ → «Установить приложение»** (или «Добавить на главный
   экран»). Появится **иконка Novel Forge** на домашнем экране. Тап по ней открывает
   приложение в отдельном окне.

3. **Ярлык-«лаунчер» на домашний экран** (одним тапом поднимать сервер), как виджет
   Термукса:
   - Установите приложение **Termux:Widget** (F-Droid).
   - Создайте папку и ярлык:
     ```bash
     mkdir -p ~/.shortcuts
     ln -sf "$PWD/launcher/start-omaya.sh" ~/.shortcuts/NovelForge.sh
     chmod +x ~/.shortcuts/NovelForge.sh
     ```
   - На домашнем экране добавьте виджет **Termux:Widget** и выберите `NovelForge.sh`.
   Теперь: тап по виджету → сервер поднимается, затем тап по иконке PWA → приложение
   в отдельном окне.

> Совет: чтобы установка «в отдельное окно» работала, нужен защищённый контекст —
> `localhost` таким считается, так что всё работает без HTTPS.

## Desktop (Windows / macOS / Linux)

1. Запустите лаунчер (или вручную `npm run build && npm run preview`):
   ```bash
   ./launcher/start-omaya.sh
   ```
2. В Chrome/Edge справа в адресной строке появится значок **«Установить»**
   (или меню **⋮ → «Установить Novel Forge»**). Приложение встанет как отдельное
   окно с ярлыком в меню/на рабочем столе.

### Linux — ярлык в меню приложений (по желанию)
```bash
sudo mkdir -p /opt/omaya && sudo cp -r . /opt/omaya
sudo cp launcher/omaya.desktop /usr/share/applications/
```
(Пути в `omaya.desktop` рассчитаны на `/opt/omaya` — поправьте, если ставите в другое
место.)

## ⚠️ Данные привязаны к порту — не меняйте адрес

Проекты, сейвы и ассеты лежат в **IndexedDB браузера**, а она привязана к origin
(`http://localhost:ПОРТ`). Разный порт = **разная база** = «пустая игра» (данные при
этом целы, просто под другим адресом).

Поэтому dev, preview и лаунчер работают на **одном порту 5173**. Если после
обновления/переезда игра оказалась пустой:

1. Откройте старый адрес — почти всегда это `http://localhost:5173`
   (`npm run dev` или лаунчер). Проект должен вернуться.
2. Если играли на другом порту (напр. `4173`) — откройте именно его
   (`PORT=4173 ./launcher/start-omaya.sh`), заберите проект через
   **Библиотека → Экспорт (.zip)**, затем откройте 5173 и **импортируйте** zip.
3. Сразу сделайте бэкап: **Библиотека → Экспорт**. Это лучший способ не потерять
   прогресс при смене устройства/браузера.

> Приложение также запрашивает у браузера «постоянное хранилище», чтобы данные не
> вытеснялись. Но НЕ играйте в режиме инкогнито — там всё стирается при закрытии.

## Параметры

- Порт: `PORT=5000 ./launcher/start-omaya.sh` (по умолчанию 5173 — не меняйте, если
  уже есть сохранённые проекты)
- Пересобрать перед запуском: `./launcher/start-omaya.sh --build`

## Как это устроено

- `public/manifest.webmanifest` — манифест приложения (имя, иконки, `display: standalone`).
- `public/sw.js` — сервис-воркер: делает приложение устанавливаемым и добавляет
  офлайн-режим. Кэшируются только свои файлы; запросы к ИИ-провайдерам не трогаются.
- `public/icons/` — иконки приложения.
- Сервис-воркер регистрируется только в собранной версии (`npm run build` + `preview`),
  а не в dev-режиме.
