# Novel Forge — установка как отдельного приложения (лаунчер)

Novel Forge — это **PWA** (Progressive Web App). После установки у него появляется
**ярлык на рабочем столе / домашнем экране**, и он открывается **в отдельном окне
без адресной строки и вкладок браузера** — как обычное приложение (аналог того, как
это сделано в SillyTavern).

## 🗄 Где лежат данные (важно для сохранности)

Лаунчер запускает свой локальный Node-сервер (`launcher/serve.mjs`), который:
- **раздаёт приложение** и **проксирует запросы к ИИ** (server-side, без CORS — как в SillyTavern);
- **пишет все данные реальными файлами на диск** в папку `vn-data/` рядом с проектом
  (источник истины). IndexedDB браузера остаётся быстрым кэшем поверх этих файлов.

Структура (близко к SillyTavern):
```
vn-data/
  <project_id>/
    project.json              — метаданные, лор, статы, конфиг, персонажи, мета ассетов
    characters/<имя>/expressions/<эмоция>.<ext>   — спрайты эмоций
    backgrounds|music|cg|sfx|icons/ ...           — ассеты как реальные файлы
    saves/<slot>.jsonl        — сейвы построчно (JSONL: meta + state + история по строкам)
```
Путь настраивается: `DATA_ROOT=/путь bash launcher/start-omaya.sh`. По умолчанию — `vn-data/`
рядом с проектом.

**Что это даёт:** очистка кэша/данных сайта в браузере (Ctrl+Shift+Delete → «данные сайта»)
**не уносит прогресс** — данные физически лежат в файлах, вне браузерного хранилища; их видно
в файловом менеджере. При первом запуске новой версии существующие проекты из IndexedDB
**один раз мигрируют** на диск. Кнопка **«Экспорт»** остаётся независимым ручным бэкапом в zip.

API-ключи — только в этом устройстве (в файлы данных не пишутся).

## 📲 Новое устройство с нуля (Termux) + перенос бэкапа

Сценарий: на старом устройстве вы сделали **Экспорт → Полный перенос (с прогрессом)**
и получили файл `<Название>-с-прогрессом.zip`. Теперь ставим приложение на новом
телефоне и загружаем в него этот бэкап.

**1. Поставить Termux.** Установите **Termux** и **Termux:API** из **F-Droid**
(версия из Play Store устаревшая и не подойдёт).

**2. Установить приложение (в Termux):**
```bash
pkg update && pkg upgrade -y
pkg install git nodejs -y
git clone https://github.com/kateomaya-beep/VN-OmayaEngine.git
cd VN-OmayaEngine
git checkout claude/app-development-31qqxy
./launcher/start-omaya.sh          # соберёт и откроет http://localhost:5173 в Chrome
```
(При желании в Chrome: **⋮ → «Установить приложение»** — появится иконка.)

**3. Перекинуть бэкап-`.zip` на новый телефон.** Любым способом — Telegram
(«Избранное»), почта, облако, USB. Сохраните файл в **Загрузки (Downloads)**.
> Импорт делается В БРАУЗЕРЕ (не командами Termux), поэтому zip просто должен
> лежать там, куда достаёт файловый выбор телефона — папка Downloads подходит.

**4. Загрузить бэкап в приложение:** откройте приложение → **Библиотека →
Импорт .zip** → выберите ваш `…-с-прогрессом.zip`. Проект появится со всем
прохождением (история, память, Game Master). Жмите **«Играть»** — продолжится
с того же места.

**5. Ввести API-ключи заново.** Ключи в бэкап НЕ входят (безопасность):
верхняя панель → **🔌 «Подключение к ИИ»** → впишите ключ и модель.

> Если в файловом выборе не видно `.zip` — нажмите «Показать все файлы» / выберите
> «Файлы» вместо галереи, либо переименуйте, оставив расширение `.zip`.

## Android (Termux) — как в Таверне

1. Установите зависимости и запустите лаунчер:
   ```bash
   cd VN-OmayaEngine
   ./launcher/start-omaya.sh
   ```
   Скрипт соберёт приложение, поднимет локальный сервер `http://localhost:5173`
   и откроет его в браузере (Chrome).

2. В Chrome нажмите меню **⋮ → «Установить приложение»** (или «Добавить на главный
   экран»). Появится **иконка Novel Forge** на домашнем экране. Тап по ней открывает
   приложение в отдельном окне.

3. **Ярлык-«лаунчер» на домашний экран** (одним тапом поднимать сервер), как виджет
   Термукса:
   - Установите приложение **Termux:Widget** (F-Droid).
   - Создайте папку и ярлык:
     ```bash
     mkdir -p ~/.shortcuts
     ln -sf "$PWD/launcher/start-omaya.sh" ~/.shortcuts/NovelForge.sh
     chmod +x ~/.shortcuts/NovelForge.sh
     ```
   - На домашнем экране добавьте виджет **Termux:Widget** и выберите `NovelForge.sh`.
   Теперь: тап по виджету → сервер поднимается, затем тап по иконке PWA → приложение
   в отдельном окне.

> Совет: чтобы установка «в отдельное окно» работала, нужен защищённый контекст —
> `localhost` таким считается, так что всё работает без HTTPS.

## Desktop (Windows / macOS / Linux)

1. Запустите лаунчер (или вручную `npm run build && npm run preview`):
   ```bash
   ./launcher/start-omaya.sh
   ```
2. В Chrome/Edge справа в адресной строке появится значок **«Установить»**
   (или меню **⋮ → «Установить Novel Forge»**). Приложение встанет как отдельное
   окно с ярлыком в меню/на рабочем столе.

### Linux — ярлык в меню приложений (по желанию)
```bash
sudo mkdir -p /opt/omaya && sudo cp -r . /opt/omaya
sudo cp launcher/omaya.desktop /usr/share/applications/
```
(Пути в `omaya.desktop` рассчитаны на `/opt/omaya` — поправьте, если ставите в другое
место.)

## 🔄 Обновление (важно — почему «вроде ничего не изменилось»)

Лаунчер запускает **собранную** версию из папки `dist/`. Если просто сделать
`git pull`, но НЕ пересобрать, — вы увидите старую сборку. Поэтому:

**Простой способ (рекомендуется):** просто запустите лаунчер — он сам сделает
`git pull` (если нет ваших локальных правок) и пересоберёт, когда код обновился:
```bash
./launcher/start-omaya.sh
```
Если хотите принудительно пересобрать: `./launcher/start-omaya.sh --build`.

**Вручную:**
```bash
cd VN-OmayaEngine
git pull                 # если ругается и вы ничего не меняли:
                         # git fetch origin && git reset --hard origin/claude/app-development-31qqxy
npm install              # вдруг обновились зависимости
npm run build            # ПЕРЕСБОРКА — без неё изменений не будет
npm run preview          # или ./launcher/start-omaya.sh
```

**После обновления обязательно обновите страницу с очисткой кэша:**
- В браузере: **Ctrl+Shift+R** (Windows/Linux) или **Cmd+Shift+R** (Mac).
- Установленное приложение (PWA) показывает старое: откройте его и сделайте
  хард-рефреш; если не помогло — DevTools → **Application → Service Workers →
  Unregister**, затем перезагрузите. На Android: Chrome → настройки сайта →
  «Очистить и сбросить», затем откройте заново.

**Если запускаете через `npm run dev`** (без лаунчера): после `git pull`
остановите сервер (Ctrl+C) и запустите `npm run dev` заново, потом хард-рефреш.

## ⚠️ Данные привязаны к порту — не меняйте адрес

Проекты, сейвы и ассеты лежат в **IndexedDB браузера**, а она привязана к origin
(`http://localhost:ПОРТ`). Разный порт = **разная база** = «пустая игра» (данные при
этом целы, просто под другим адресом).

Поэтому dev, preview и лаунчер работают на **одном порту 5173**. Если после
обновления/переезда игра оказалась пустой:

1. Откройте старый адрес — почти всегда это `http://localhost:5173`
   (`npm run dev` или лаунчер). Проект должен вернуться.
2. Если играли на другом порту (напр. `4173`) — откройте именно его
   (`PORT=4173 ./launcher/start-omaya.sh`), заберите проект через
   **Библиотека → Экспорт (.zip)**, затем откройте 5173 и **импортируйте** zip.
3. Сразу сделайте бэкап: **Библиотека → Экспорт**. Это лучший способ не потерять
   прогресс при смене устройства/браузера.

> Приложение также запрашивает у браузера «постоянное хранилище», чтобы данные не
> вытеснялись. Но НЕ играйте в режиме инкогнито — там всё стирается при закрытии.

## Параметры

- Порт: `PORT=5000 ./launcher/start-omaya.sh` (по умолчанию 5173 — не меняйте, если
  уже есть сохранённые проекты)
- Пересобрать перед запуском: `./launcher/start-omaya.sh --build`

## Как это устроено

- `public/manifest.webmanifest` — манифест приложения (имя, иконки, `display: standalone`).
- `public/sw.js` — сервис-воркер: делает приложение устанавливаемым и добавляет
  офлайн-режим. Кэшируются только свои файлы; запросы к ИИ-провайдерам не трогаются.
- `public/icons/` — иконки приложения.
- Сервис-воркер регистрируется только в собранной версии (`npm run build` + `preview`),
  а не в dev-режиме.
