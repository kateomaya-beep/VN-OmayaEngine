# Novel Forge — Конструктор ИИ-визуальных новелл

Web-приложение для **конструирования** визуальных новелл в духе «Клуба Романтики»,
где нарратив в реальном времени генерирует LLM (BYO API key). Пользователь загружает
ассеты, прописывает лор, персонажей и статы, а движок парсит структурированный вывод
ИИ и рендерит его как классическую новеллу: фон, спрайты с эмоциями, диалоговое окно,
выборы, изменения статов.

**Аналогия:** SillyTavern (ядро LLM) + Ren'Py (презентация) + конструктор без кода.

## Ключевые принципы

- **Клиентское SPA без бэкенда.** Всё хранится локально: проекты, ассеты (Blob) и
  сейвы — в IndexedDB. Экспорт/импорт проекта одним `.zip`.
- **BYO API key.** Ключи хранятся только в `localStorage` и уходят напрямую к
  выбранному провайдеру (OpenAI-совместимый / Anthropic). Больше никуда.
- **ИИ не видит файлы** — только манифест ассетов (id + имя + теги) и выбирает id
  по тегам. Галлюцинированные id не ломают рендер (fallback-политика).

## Стек

React 18 · TypeScript · Vite · Zustand · IndexedDB (`idb`) · Tailwind CSS ·
Howler.js (кроссфейд музыки) · JSZip · Zod · React Router.

## Запуск

```bash
npm install
npm run dev       # http://localhost:5173
npm run build     # продакшн-сборка в dist/
npm run preview   # предпросмотр сборки
```

## Как пользоваться

1. **Библиотека** → «Новый проект».
2. **Конструктор** — вкладки:
   - *Настройки* — название, жанр, обложка, рейтинг.
   - *Лор* — мир, арка сюжета, стартовая сцена, правила повествования.
   - *Персонажи* — анкеты + **SpriteBinder** (спрайты по эмоциям, обязателен `neutral`).
   - *Статы* — границы, стартовое значение, иконка, видимость, описание для ИИ.
   - *Ассеты* — мультизагрузка фонов/спрайтов/музыки/CG/иконок, автотеги, чипы-теги.
   - *Лорбук* — записи с ключами-триггерами и тест-полем (как в SillyTavern).
   - *ИИ / Промпт* — провайдер, модель, API-ключ, параметры, Director Prompt.
3. **Валидатор** вверху подсвечивает проблемы (нет стартовой сцены / фона / спрайтов ЛИ).
4. **▶ Играть** — рантайм: фон с кроссфейдом, спрайты, тайпрайтер, выборы (в т.ч.
   платные за статы), HUD статов с анимацией, история, сейвы (1–10 + автосейв),
   перегенерация хода, экран «Память истории».

```
│   ├── responseParser  извлечение JSON, Zod-валидация, ремонт id по манифесту, кламп статов

```

## Формат ответа ИИ

ИИ обязан отвечать одним JSON-объектом: `scene` (id фона/музыки/sfx/CG),
`beats` (narration / thought / dialogue с эмоцией и позицией), `statChanges`,
`choices` (с опциональным `cost`), `chapterEvent`. Парсер извлекает JSON из
возможных markdown-фенсов, валидирует Zod-схемой, чинит невалидные id по манифесту
(неизвестный фон → текущий, неизвестная эмоция → `neutral`, неизвестный персонаж →
narration) и клампит статы. При невалидном JSON — один авто-retry, затем ошибка
с кнопкой «Повторить».

## Память (при сколь угодно длинной игре)

Трёхслойная: **Хроника** (саммари прошлых глав) → **Текущая глава** (саммари начала)
→ **Живое окно** (последние K ходов дословно). Сжатие срабатывает по бюджету токенов
и по событию `chapter_end`. Отдельно ведётся **Canonical Facts Store** (выборы игрока,
`statChanges`, вехи) — эти данные не проходят через LLM-сжатие. Всё состояние памяти
входит в сейв.
